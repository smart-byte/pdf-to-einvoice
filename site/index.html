Turn the invoice PDF you already have into an e-invoice.

Your invoice looks as it did. The invoice data is added in machine-readable form, as XML following EN 16931 (ZUGFeRD / Factur-X).

Nothing is uploaded. Everything happens in your browser.

  • Open source (MIT)

Create as

For invoices to public bodies and other public-sector buyers. It also needs the Leitweg-ID or another buyer reference, a contact person with phone and email, and the buyer's email address.

Read with AI

A language model reads names, addresses and line items from the text of your invoice. The models in the list run on your device; your invoice does not leave the browser.

The model (about 1 GB) is downloaded from huggingface.co and raw.githubusercontent.com on first use and kept in the browser.

The text of your invoice is sent to this address. If it is not on your device, the text leaves your device.

You can keep working while the model loads; it is kept for next time.

    Compared
    
          
    Many services convert PDF invoices too. The main difference is where your invoice is processed.
    
        
    
        
        
    
          
            
    
              
              Typical online converter
              pdf-to-einvoice
            
    
              
          
            
    
              Where is your invoice processed?
              
                Typical online converterOn the provider's servers: the file is uploaded.
              
              pdf-to-einvoiceOn your device, in the browser. Nothing is uploaded.
            
    
            
    
              Who reads the data?
              
                Typical online converterDepending on the provider, an AI service in the cloud, also outside the EU, or you type everything in.
              
              
                pdf-to-einvoiceRules on your device; on request also a language model that runs in your browser too, or a service whose address you enter yourself.
              
            
    
            
    
              Where does each value come from?
              
                Typical online converterYou get a form to correct.
              
              
                pdf-to-einvoiceWhat was read from the PDF is marked on it. Numbers, names, addresses, dates, prices and totals are compared with its text: whether they are
                  there, not where.
              
            
    
            
    
              Account, ads, tracking
              
                Typical online converterDepending on the provider, sign-up, ads or a subscription.
              
              pdf-to-einvoiceNo sign-up, no ads, no cookies.
            
    
            
    
              Source code
              Typical online converterMostly closed.
              
                pdf-to-einvoiceOpen (MIT licence): anyone can check what the page does.
              
            
    
            
    
              For software and AI assistants
              
                Typical online converterMostly an API that invoices are sent to.
              
              
                pdf-to-einvoiceLibrary, command line tool and MCP server, all on your own machine.
              
            
    
            
    
              Formats
              
                Typical online converterZUGFeRD, often XRechnung and more.
              
              pdf-to-einvoiceZUGFeRD / Factur-X and XRechnung, following EN 16931.
            
    
            
    
              Checking against the official rule sets
              
                Typical online converterSome offer their own validator.
              
              
                pdf-to-einvoiceIts own plausibility check; not a complete check against the official rule sets.

import { check, createEInvoice, extractLayout, guessFromText } from 'pdf-to-einvoice';

const { text, blocks } = await extractLayout(pdfBytes);
const invoice = guessFromText(text, { blocks }); // what the page says
const { findings } = check(invoice, { pdfText: text }); // what is missing or wrong
const { pdf, xml } = await createEInvoice({ pdf: pdfBytes, invoice });
    
          
          
    npx pdf-to-einvoice read invoice.pdf --json # text, guessed values, facts about the file

npx pdf-to-einvoice create invoice.pdf data.json # writes invoice.einvoice.pdf
npx pdf-to-einvoice validate invoice.einvoice.pdf # checks an existing e-invoice

    # skills/pdf-to-einvoice/SKILL.md ships with the package. Its rules for an agent:

- You act for the invoice issuer. A received PDF cannot be turned into a valid e-invoice.
- Copy values exactly as the PDF prints them. Never invent a value; ask the user.
- Always show the findings. Errors block the e-invoice.
- Get the user's confirmation of the data before you create the file.
